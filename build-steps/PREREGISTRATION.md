# Pre-Registration — Self-Improvement Loop OOS Gate

**Registered:** 2026-06-02 · **Status:** active · **Supersedes:** the in-sample-only loop (no holdout) that ran iterations EXP-005…EXP-009.

This document is registered *before* the loop runs under the holdout gate. Its
thresholds are fixed. They are not to be weakened mid-run; weakening them is
itself a form of the multiple-testing failure this gate exists to prevent. If a
threshold must change, the change is logged here with a date and the trial
counter `N` is **not** reset.

---

## H0 — the null hypothesis

> **There is no edge at minute 13 of a Polymarket BTC 15-minute market.** The
> strategy is EV-negative net of the realistic spread + Polymarket fee cost
> model. No code change discovered by in-sample hill-climbing will produce a
> positive, generalising edge.

This is the standing prior, and it is well-supported before the loop even runs:

- Train-only baseline (`.claude/state/baseline.json`): mean PnL **−$0.0026/trade**,
  n=15,084, bootstrap 95% CI [−0.0078, +0.0025].
- 9 loop iterations under the prior (in-sample) regime produced **0 accepts**.
- The headline 92% win rate is a negative-skew "pick up pennies" structure: the
  ~7¢ round-trip fee in the current regime is larger than the per-trade edge.

**The holdout's job is to prevent false accepts, not to manufacture an edge.**
The expected and acceptable outcome of this loop is "no candidate survives
holdout." A run that ends with zero candidates is a *successful* run.

## Split definition (immutable once a run begins)

Generated by `build-steps/real_backtester.py --build-splits`:

| | definition | value (2026-06-02 rebuild) |
|---|---|---|
| **Holdout** | most recent `--holdout-days` of the dataset | 30 days → 2026-05-02 … 2026-06-01, n=2,135 |
| **Embargo** | `--embargo-hours` dropped from BOTH sides of the boundary | **48h**, 192 markets dropped |
| **Train** | everything before the embargo | n=16,855 markets / 15,084 trades |

**Embargo = 48h (not the 24h default).** The backtester's `price_history` /
`tick_buffer` deques are *not* cleared on market switch (it mirrors `bot.py`), and
the sentiment feature reads a **daily** Fear & Greed index. A 24h embargo barely
covers the daily-feature horizon plus the cross-market deque carryover; 48h
clears both with margin, at a cost of ~1 extra dropped day out of 30. Recorded in
each split file as `embargo_seconds: 172800`.

Split files (`build-steps/data/splits/{train,holdout}_market_ids.json`) are
guard-frozen for editing; only `--build-splits` rewrites them, and only **between**
runs, never mid-run.

## The two-stage accept gate (locked thresholds)

A candidate must clear an in-sample screen on **TRAIN**, and only then be
confirmed **once** on the untouched **HOLDOUT**.

### Stage 1 — TRAIN screen (holdout never touched)
Computed by the Tester on `--split train`, evaluated by the Statistician:

| condition | verdict |
|---|---|
| backtest crashed | `crashed_on_train` (stop) |
| `overall_ev_lift <= 0` | `reject_on_train` (stop) |
| `overall_ev_lift > 0` but NOT(`ci_lower>0` AND `dsr>=0.95` AND `retention>=0.80`) | `indistinguishable` (stop) |
| `overall_ev_lift > 0` AND `ci_lower>0` AND `dsr>=0.95` AND `retention>=0.80` | → **proceed to Stage 2** |

- `overall_ev_lift` = train mean PnL (post-change) − train baseline mean PnL.
- `ci_lower` = lower bound of the bootstrap 95% CI on post-change train mean PnL.
- `dsr` = Deflated Sharpe Ratio (see N protocol below); gate **0.95**.
- `retention` = (post-change trade count) / (baseline trade count); gate **0.80**.
  A skip that merely makes a losing strategy *less* losing is `indistinguishable`,
  not a candidate.

### Stage 2 — HOLDOUT confirmation (scored exactly once)
Run by the Statistician only, on `--split holdout`, only for a Stage-1 survivor:

| condition on holdout | verdict |
|---|---|
| `holdout_ev > 0` AND `holdout_ci_lower > 0` | **`candidate`** |
| `holdout_ev > 0` AND `holdout_ci_lower <= 0` | `reject_on_holdout` |
| `holdout_ev <= 0` | `reject_on_holdout` |

A `candidate` is an **in-sample-plus-one-OOS-window** result, NOT a profitable
strategy. It is flagged for live paper validation, never deployed on its backtest
alone. A candidate does **not** auto-stop the loop.

## N protocol (multiple-testing penalty)

- **N = cumulative count of all configurations ever tried** =
  `wc -l .claude/state/experiments.jsonl + 1`. Monotonically non-decreasing; it is
  **never reset**, including across the in-sample→holdout regime change.
- The Deflated Sharpe Ratio (`build-steps/stats/deflated_sharpe.py`) is recomputed
  every iteration with the **current cumulative N**, so the bar `E[max SR | N]`
  tightens as the search continues. A change that cleared DSR at N=50 can fail at
  N=500 — that rising bar is the multiple-testing tax made explicit.
- **Out of scope (documented future hook):** effective-N via trial-PnL clustering
  (López de Prado 2018). Raw cumulative N over-penalises correlated trials, so the
  current DSR errs *conservative* — toward rejecting — which is acceptable given
  H0. When added, cluster trials by `cluster_filter` / `files_changed` similarity
  and pass an effective N to `deflated_sharpe`.

## Single-use holdout rule

- The **Reviewer** and **Tester** never see the holdout. The Reviewer mines
  `build-steps/data/backtest_trades.csv`, which the orchestrator regenerates with
  `--split train`. The Tester runs `--split train` only and is structurally
  forbidden from `--split holdout`.
- The **Statistician** is the only agent permitted to run `--split holdout`, and
  only for a Stage-1 survivor, at most once per iteration. The single use is
  recorded in `.claude/state/holdout_lock.json` as
  `{"last_iter": NNN, "last_ts": "<iso>"}` for audit.
- Enforcement is structural + auditable, not hook-enforced (the PreToolUse
  `guard.py` cannot see which subagent issues a Bash call). The guarantees are:
  (a) only `statistician.md` contains the string `--split holdout`; (b) the
  orchestrator/Tester/Reviewer specs contain `--split train` only; (c) the lock
  file provides the audit trail. A static grep of the four committed specs is part
  of the verification checklist.

## Methodological references

- Bailey & López de Prado (2014), *The Deflated Sharpe Ratio* — the N-penalty.
- Bailey, Borwein, López de Prado, Zhu (2017), *The Probability of Backtest
  Overfitting* (CSCV) — the standard PBO method; the future-hook companion to DSR.
- Bailey & López de Prado (2012), *The Sharpe Ratio Efficient Frontier* — PSR /
  Minimum Track Record Length; why a sub-cent edge with negative skew needs a very
  long track to distinguish from zero.
