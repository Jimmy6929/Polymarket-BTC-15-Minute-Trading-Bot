  3. "You modeled the only losing side and ignored the only winning one." Everything here is

  The half they'd tear apart

  Now the trench coat opens. The README sells "multiple signal sources," "self-learning capabilities," a
  "7-phase architecture," "production-grade." The code says otherwise, and a quant checks:

  - "Multiple signal sources" is false. Six signal processors run, fuse with weighted voting… and then
  the fused direction is thrown away and overwritten by a one-line trend rule: if mid > 0.60 buy YES, if
  < 0.40 buy NO, else skip (bot.py:1044-1080). The entire signal/fusion stack is logged-but-ignored.
  The actual strategy is "buy the price you see." The fusion engine is working theater.
  - "Self-learning" is false in a way that's almost poetic. The learning engine adjusts weights based on
  performance_tracker.get_trade_history() — and performance_tracker is never written to anywhere in the
  bot. It optimizes over an empty list. It is also never called in the main loop.
  (feedback/learning_engine.py:196-249, confirmed independently.)
  - The execution layer cannot touch live capital, full stop. Order IDs are
  f"order_{counter}_{timestamp}" — non-idempotent, the counter resets on crash, so a reconnect can
  double-submit (execution_engine.py:234). There's no websocket reconnection logic, no fill-event
  listener (so a live fill never creates a position — the callbacks only fire in dry-run), order state
  is in-memory only, and polymarket_client.py — labeled "Production Implementation" — is unintegrated 
  dead code whose get_btc_market() returns a hardcoded mock with a TODO. The live path runs through
  Nautilus as fire-and-forget.
  - The infra is built for a live stage that doesn't exist. Grafana 12-panel dashboard, Prometheus
  exporter, Redis mode-switching — all present, all idle, none wired into anything that runs. The loop's
  actual durable state is plain JSON files in .claude/state/ (which, credit where due, is the right
  tool and works).

  The one piece of the engineering that's genuinely sound: the risk engine enforces limits pre-trade ($1
  size, $10 exposure, rejects before submission). Though even there — no daily reset, no kill-switch
  halt on repeated rejects, drawdown measured off a hardcoded $1000 peak
